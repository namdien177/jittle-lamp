Feature proposal

Biến Jittle Lamp thành nền tảng E2E có AI dẫn dắt

Test case là một transcript. Agent đọc transcript, mở Chrome thật, làm từng bước như một tester, ghi lại evidence. Mỗi bước đã chạy đúng được giữ lại thành script; lần sau replay script trước, chỉ gọi model khi app thay đổi.

Transcript[Act], [Assert], [Login: PCF], checkpoint headings. Nguồn sự thật.packages/shared/test-case.ts
RunnerTester Army e2e + AI SDK + Playwright. Daemon trong cloud pool, self-hosted pool trên devbox, hoặc CLI local.packages/e2e-runner
Evidencerecording.webm + archive v4 + run-report.json. Viewer, share link, MCP dùng lại.sourceType: test-run
Step scriptsAction record (role/name/testId/context) render ra Playwright. Replay, hand-off, re-record.test_step_scripts
Test sessionsMỗi run có verdict 2 tầng, step results, video offset, cost.test_runs / test_run_steps
Tại sao làm

Recording hiện tại không tái hiện được

  • Recording tách rời test case, ticket, tài liệu.
  • Instruction viết tay hoặc quá chi tiết, hoặc sai; không ai chạy lại được.
  • Flow thủ công đã có: Claude Code + record-flow.mjs + jl-evidence.mjs. Feature này đưa flow đó vào sản phẩm.
Học từ reference

Tester Army cho mô hình, Browserbase cho đối chiếu

  • Tester Army: step types act/assert/login, verdict tách execution và outcome, cache là action record có end-state check, hand-off khi drift.
  • Stagehand v4 bỏ Playwright và đưa cache lên server của Browserbase. Không dùng làm nền; giữ làm candidate sau interface step.
  • Khác biệt của mình: mọi instruction đều có code đọc được, assert cũng cache deterministic check.

Chọn: e2e làm core, packages/e2e-runner bọc ngoài: transcript → case.e2e.ts + e2e.config.ts, cache.store trỏ vào test_step_scripts, Reporter stream step events, parse ai-trace.json lấy token, trace → archive v4. Gate cuối phase 0: đổi sang loop riêng trên AI SDK nếu route file sinh không diễn đạt được transcript, token per step không tin được, trace thiếu dữ liệu viewer cần, hoặc e2e đổi contract 2 lần trong spike.

ADR 0002 · đã chốt
  1. Transcript là nguồn sự thật. Code sinh ra là cache gắn vào step, không sửa tay.
  2. Cache là action record, không phải selector thô. Render ra Playwright TS để đọc và export; replay bằng nhiều chiến lược locator; hand-off cho agent khi mất target hoặc sai end-state.
  3. Runner là daemon riêng; cloud pool trước, self-hosted pool cho mạng cloud không tới được, desktop chỉ là client. Sửa 2026-10-03. Một binary vừa là CLI jl-e2e vừa là daemon jl-e2e-runner, đăng ký vào pool bằng token, claim run bằng lease. Environment gắn với pool, nên UAT sau VPN chạy trên runner đặt ở devbox. Desktop app trigger run và review evidence, không điều khiển browser.
  4. Run là evidence. sourceType: "test-run", action tag step:<id>, annotation step.
  5. Model đi qua Vercel AI SDK, không gắn vendor SDK. Sửa 2026-10-03, trước đó là Anthropic SDK. Org cấu hình model (act) và judge (assert/wait/extract) là AI SDK id, mặc định anthropic/claude-opus-5-5 và anthropic/claude-sonnet-5-5; provider option (adaptive thinking, effort) đi qua providerOptions.
  6. Verdict 2 tầng. status: queued/running/completed/failed/cancelled. outcome: passed/failed/blocked. Lỗi setup là blocked, không bao giờ là failed.
  7. Macro có tham số đặt tên. [Login: profile=PCF, tenant=HQ]. Người tạo, code seed, hoặc agent đề xuất qua MCP (draft cho tới khi duyệt).
  8. Archive schema v4. recorder.kind thêm e2e-runner; parser nâng v3 trong bộ nhớ.
  9. Mỗi run và mỗi step lưu đủ metrics. model id (act và judge), provider, model calls, input / cached / output / reasoning tokens, duration, cost. AI SDK trả token, không trả tiền, nên cost tính từ test_model_prices của org lúc finalise và stamp version bảng giá vào run. Test case hiện trung bình 10 run gần nhất.
  10. Execution core là Tester Army e2e, có gate cuối phase 0. Step semantics, replay cache (pluggable cache.store), AI SDK contract, video + trace khớp thiết kế. Không có API programmatic nên runner sinh case.e2e.ts + config rồi spawn e2e run. Stagehand loại: cache theo xpath, không có verdict, v4 bỏ Playwright.
  11. Run trên cloud là headless với tiến độ step trực tiếp; headed và khoá input là tính năng của CLI local; live view kèm take-over để phase 2. Runner báo mỗi step xong kèm screenshot thu nhỏ, video gắn lúc kết thúc. jl-e2e run --headed giữ shield, phát hiện input thật thì pause. Take-over: pause, action tag user:takeover, không cache.
  12. Một queue mỗi org, dedupe và throttle. max_concurrent_runs mặc định 1 cho cloud pool. Cùng dedupe_key (case, version, env, params, cache mode) thì attach vào run đang chờ hoặc vừa xong trong dedupe window; force mới tạo run mới. Queue cap theo org và case, token bucket theo user.
  13. Authoring cho hàng ngàn case, một document format cho mọi đường vào. Người dùng nhập tay bằng step editor có cấu trúc (chip, picker / { @, lint sửa được), markdown chỉ là format lưu trữ và trao đổi. AI, Jira, Gherkin, CSV/XLSX, TestRail đều ra transcript document; lint và phát hiện trùng chạy một lần. Import và AI vào review queue. Case gần giống là case có dataset; duplicate thật ghi lineage và kế thừa step scripts. Folders, tags, suites, saved views trên FTS, key TC-0412.
  14. BYOK theo org. Org lưu một provider key và model id cho act/judge; mọi run dùng key đó, chi phí quy về user yêu cầu qua metrics. Beta không có key cá nhân.
  15. Test case scope theo org, nhóm bằng tag có namespace. team:, feature:, module:, prio: do org quản lý; sidebar nhóm theo namespace. Không folder, không team scope. Suite và saved view xây trên tag.
  16. Notification qua bus theo channel; beta chỉ có in-app. Producer ghi notification_events; channel in-app giao ngay, Slack và email là adapter thêm sau, không đụng producer.
  17. Trigger từ GitLab/GitHub là webhook, thiết kế bây giờ, giao ở phase 2. Endpoint có chữ ký, rule map event sang suite + environment (review-app URL vào baseUrl), dedupe theo commit SHA, báo lại bằng commit status, MR note hoặc callback URL. Beta dùng CLI trong pipeline.
  18. Một chuỗi resolve cho variables và credentials. Code chỉ gọi tên: env.baseUrl, vars.KEY, secret('PROFILE.field'). Runner resolve theo thứ tự run params → process env (JL_ENV_*, JL_VAR_*, JL_CRED_* từ .env) → desktop keychain → org config trên backend. Cloud worker bơm org config vào env của runner, nên cloud và local chạy cùng một đường.
Format

Transcript playground

Sửa bên trái, parser thật chạy bên phải. Đây là Text view và format lưu trữ, không phải cách người dùng nhập tay: editor chính là step editor có cấu trúc (xem UI mẫu). Cùng grammar sẽ nằm trong packages/shared: dòng [Tag: args] text, heading ## Checkpoint: gom các bước, text trần là Act, tag lạ tra macro của org.

    Config · cloud và local chạy cùng một đường

    Cloud

    • Settings → Environments: name, base URL, variables (plaintext).
    • Settings → Credentials: profile, public fields, secret fields mã hoá AES-256-GCM, data key theo org, master key server (provider pluggable, rotate bằng key_version).
    • Permission test_config.manage / test_config.use; mỗi lần đọc secret ghi activity log kèm run id.
    • Runner pool: jl-e2e-runner start --token đăng ký worker vào pool (cloud hoặc self-hosted); environment gắn pool. Worker claim run → config-token → GET /test-runs/:id/config → bơm thành JL_* env cho runner con. Không route nào trả secret về browser.
    • Model key BYOK theo org lưu như credential kind: model_key.

    Phasing

    Roadmap

    Phase 0 là spike để kiểm chứng giả định quan trọng nhất: replay toàn bộ Act step với 0 model call ở lần chạy thứ hai, trên một case UAT thật.

    Phase 0 · 1–2 tuần

    Spike

    • packages/e2e-runner bọc Tester Army e2e, CLI only
    • parser transcript trong packages/shared → sinh case.e2e.ts
    • cache file JSON qua cache.store
    • trace → archive v4, upload qua /automation/evidences/zip
    • thử Input.setIgnoreInputEvents vs shield
    Exit: một case PCF/ILHAM từ _bdd chạy 2 lần, lần 2 replay mọi Act step với 0 model call cho Act; evidence mở được trong viewer; token per step đọc được từ ai-trace. Gate: giữ e2e hay chuyển loop riêng.
    Phase 1

    MVP

    • tables, routes, permissions, AI allowlist
    • archive v4 + viewer lọc theo step
    • web: test case pages, run detail step-seek
    • Authoring: multi-case document, import .md/.feature/.csv, duplicate kế thừa scripts, review queue, FTS, folders/tags/suites
    • Cloud runner pool + self-hosted pool: daemon, đăng ký, lease worker, config token
    • Environments + Credentials settings, secret mã hoá server, BYOK model key
    • desktop và web là client, tiến độ step trực tiếp
    • in-app notifications; Jira import; .feature import
    • CLI jl-e2e: .env, env pull, export/push
    • MCP tools; macro có tham số
    Exit: tester tạo case trên web, chạy từ desktop, review run có step-seek, re-run với cache; agent tạo và chạy case qua MCP.
    Phase 2

    Platform

    • webhook GitLab/GitHub + báo status về MR
    • Slack channel
    • live view cloud browser + take-over
    • agent notes (org memory)
    • GitHub Actions / GitLab CI template
    • strict cache trong CI, JUnit export
    • Jira comment integration
    Exit: pipeline CI chạy một group case bằng automation token và post kết quả.
    Phase 3

    Bridges

    • import evidence sẵn có vào test case, link chéo hai chiều
    • sinh transcript nháp từ manual recording (archive interactions → model → draft)
    • agent tự đề xuất macro từ sequence lặp
    Exit: recording cũ gắn được vào case; session thủ công cho ra draft chạy được.

    Phase 1 dùng thẳng Anthropic SDK. Nếu cần provider khác, bọc agent sau một ModelClient nhỏ thay vì chọn multi-provider SDK ngay.

    Headed để tester xem và can thiệp, nhưng cửa sổ Chrome nổi lên làm đổi focus. Mặc định headed, có tuỳ chọn "run in background".
